## Project Overview

Full-stack web application for a Turkish construction company (Akinal İnşaat). It has a public-facing marketing site and a protected admin panel for project/finance management.

- **Frontend**: React 18 + Vite + TypeScript + Tailwind CSS + shadcn/ui
- **Backend**: PHP 8+ REST API
- **Database**: MySQL (shared cPanel hosting)
- **Deployment**: FTP via `deploy-akinal.bat` (Windows) → `npm run build` then `python scripts/deploy_ftp.py`

## Commands

```bash
npm run dev          # Start Vite dev server
npm run build        # Production build (outputs to dist/)
npm run lint         # ESLint
npm run test         # Run all tests (vitest, single pass)
npm run test:watch   # Watch mode
npm run seed:demo    # Seed demo data (Node.js MJS script via API)
```

## Architecture

### Frontend (`src/`)

**Two distinct sections share one router:**
- **Public site** (`src/pages/site/`): Marketing pages served at `/`
- **Admin panel** (`src/pages/admin/`): Protected at `/admin`, wrapped in `AdminLayout`

All route components in `App.tsx` are lazy-loaded. The admin layout (`src/components/admin/AdminLayout.tsx`) defines the sidebar navigation in the `NAV_GROUPS` array — add new routes there when adding admin pages.

Key frontend files:
- `src/lib/apiClient.ts` — every API call goes through `apiGet()` or `apiRequest()` wrappers here; add new API functions here
- `src/lib/apiTypes.ts` — all shared TypeScript interfaces
- `src/lib/finance.ts` — finance constants, type aliases, calculation helpers
- `src/lib/customerMasterData.ts` — customer-specific finance helpers

State management uses **TanStack Query** for all server state. Forms use **react-hook-form + zod**.

### Backend (`public_html/api/`)

Every admin endpoint is a single PHP file in `public_html/api/admin/` that handles GET/POST/PATCH/DELETE by inspecting `$_SERVER['REQUEST_METHOD']`.

**Required boilerplate at the top of every admin API file:**
```php
<?php
declare(strict_types=1);
require_once __DIR__ . '/helpers.php';
require_admin(); // enforces session auth, 401/403 on failure
```

Core infrastructure:
- `api/response.php` — `json_success(array $data, int $status)` and `json_error(string $message, int $status)` (both call `exit`)
- `api/db.php` — singleton `db(): PDO` function; reads DB credentials from `api/config.php` (not in repo)
- `api/auth.php` — `require_admin()`, `current_admin()`, session helpers
- `api/admin/helpers.php` — `uuid_v4()`, `require_non_empty()`, `require_iso_date()`, `require_allowed_value()`, `nullable_string()`, `require_positive_amount()`

**Response envelope**: every response is `{ "success": true, "data": {...} }` or `{ "success": false, "message": "..." }`. The frontend `apiGet`/`apiRequest` unwraps `data` automatically.

### Database

All tables are prefixed `ak_`. All PKs are `CHAR(36)` UUIDs generated by `uuid_v4()` in PHP. Timestamps follow `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP` pattern. All tables use `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`.

Schema installer: `public_html/install-schema.php` — gated behind `ENABLE_SETUP_TOOL = false` and a query-param confirmation. Tables use `CREATE TABLE IF NOT EXISTS` (idempotent).

### Market Rates

`public_html/api/admin/market-rates.php` fetches live FX rates (EUR/USD/gram gold) from external sources with a 5-minute server-side file cache in `sys_get_temp_dir()`. Frontend calls `getAdminMarketRates()` to prefill exchange rates in financial entry forms. Exchange rates saved with entries are immutable snapshots — they must never be auto-updated when the live rate changes.

### Tests

Vitest with jsdom. Test files: `src/**/*.{test,spec}.{ts,tsx}`. Setup: `src/test/setup.ts` (jest-dom + matchMedia stub). There are no PHP unit tests; PHP is validated with `php -l` and integration-tested via the seed/smoke scripts.

## Finance Architecture (In Transition)

The project is migrating from a dual-track legacy finance system to a new card-based architecture. The legacy system has two parallel tracks:
- Legacy: `ak_payments` (income) + `ak_expenses` (costs)
- Canonical: `ak_financial_entries` (unified ledger)

Both tracks are currently read by `dashboard.php`, gated by `canonical-read-flags.php`. The new target architecture uses four owner-specific entry tables (`ak_customer_financial_entries`, `ak_employee_financial_entries`, `ak_supplier_financial_entries`, `ak_expense_card_financial_entries`) plus a new `ak_suppliers` master table. Legacy finance tables and pages are being deprecated. See `docs/GLOBAL_TABLE_DEPENDENCY_AUDIT.md` and the owner constitution for full details.

Three schema-only tables with no active queries that can be dropped when safe: `ak_profiles`, `ak_user_roles`, `ak_customer_notes`.
